# Тест-план та критерії приймання

Статус усіх сценаріїв: NOT RUN. Це специфікація тестів; тести реалізуються разом з відповідним етапом.
Тестові seed: 1, 42, 20260920. Fixture задають tick, масу й позиції без випадкового спавну. Floating-point порівняння: абсолютна похибка <=1e-6 для формул; snapshot replay у тому самому runtime має бути тотожним після стабільної серіалізації.

## Рівні

- Unit: формули, межі, поглинання, порядок, RNG, стани ботів.
- Property: маса/позиції скінченні, мертві не рухаються, ID унікальні, їжа поглинається лише раз.
- Integration: World+боти+Session; сервер+реальні WebSocket-клієнти.
- Browser E2E: реальний Chrome, клавіатура/миша, UI, WebGL.
- Manual hardware: Quest 2, tracking, стереоскопія, комфорт.
- Load/soak: сервер, тривалі матчі, пам'ять, мережа, частота кадрів.

## Performance-процедура

Еталонний ноутбук — Windows 11, Chrome stable, 16 GiB RAM, Intel Iris Xe класу i5-1135G7, живлення від мережі, 1280×720, low; це цільовий клас, фактичну модель/CPU/GPU/драйвер зафіксувати перед прийманням. Якщо доступний лише потужніший ПК, S1-04 лишається неперевіреним.
Quest 2 — записати OS/browser versions, режим Hz, якість, заряд, фонові програми. Сервер — Linux 4 vCPU/8 GiB, точний провайдер/CPU/runtime і мережевий регіон у звіті.

Сцена: 800 їжі, 9 клітин (1+8), seed42; окремий stress-fixture з 9 великими клітинами поруч для overdraw. Прогрів 2 min, вимір desktop 10 min, Quest 20 min; автоматично перезапускати п'ятихвилинні матчі без втручання у правила. Три повтори, оцінювати кожен.
Desktop: median frame interval <=17.5 ms, p95 <=20 ms, кадрів >33.3 ms <1%.
Quest 72 Hz: median <=14.5 ms, p95 <=15.5 ms, пропущених compositor кадрів <1%; при 90 Hz встановити відповідний жорсткіший профіль. Самого JS FPS недостатньо — потрібні headset/browser performance counters.
CPU simulation p95 <=4 ms/tick на ноутбуці та <=3 ms на Quest. Зниження якості не приховує ворогів.
Сервер: tick duration p95 <=8 ms, p99 <=16.67 ms; немає сталого відставання >100 ms; RSS <=2 GiB для тестового навантаження, приріст після прогріву <10% за годину. Для клієнта після 10 циклів та GC retained heap не росте >10%; відсутні від'єднані canvas/активні старі loop.
Мережа: виміряти snapshot bytes, egress/client, RTT, corrections, queue depth. Перевірити межі з 06.

## Звіт та ворота

Звіт: дата, commit/buildId, rulesVersion, пристрої/версії, seed/config, сценарій, кроки, expected/actual, PASS/FAIL/BLOCKED, логи/відео/trace, дефекти, відповідальний.
P0 — втрата контролю/краш усіх/порушення серверної довіри; P1 — зламаний цикл або базова вимога; P2 — локальний дефект з обходом; P3 — косметика.
Випуск: усі обов'язкові сценарії етапу PASS, немає P0/P1, кожен P2 має рішення про прийняття й опис обходу. Відсутній Quest чи серверний тест позначається BLOCKED, ніколи PASS.
Мінімальне покриття core — 90% branches, але відсоток не замінює граничних сценаріїв. Падіння тесту має відтворюватися seed/fixture.
